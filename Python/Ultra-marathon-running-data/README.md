# Ultra Marathon Running - Exploratory Data Analysis (Python)

## Overview

Data cleaning and exploratory analysis project focusing on **100 km ultra-marathon races held in Poland between 2010 and 2018**.

The project starts from a global historical dataset containing more than 7.4 million race results and narrows it to the selected Polish 100 km events for analysis of participation, demographics, and performance patterns.

Dataset source: [Kaggle - The Big Dataset of Ultra Marathon Running](https://www.kaggle.com/datasets/aiaiaidavid/the-big-dataset-of-ultra-marathon-running)

## Data Processing Pipeline

### 1. Data Acquisition
- Kaggle API integration for dataset download
- ZIP extraction
- CSV loading with mixed-type handling

### 2. Filtering & Scoping
- Filter to events containing `(POL)`
- Keep only **100 km** races
- Restrict event years to **2010-2018**
- Create a dedicated analysis copy of the filtered data

### 3. Data Cleaning & Feature Engineering

#### Event Name Standardization
- Remove redundant `(POL)` suffix
- Strip formatting whitespace

#### Athlete Age
Athlete age is calculated relative to the year of the race:

```python
athlete_age = event_year - athlete_year_of_birth
```

This represents approximate age at the time of the event rather than age relative to the current year.

#### Performance-Time Cleaning
- Remove trailing `h` markers from performance strings
- Preserve the original `HH:MM:SS` structure

#### Average-Speed Cleaning
- Convert `Athlete average speed` to numeric
- Invalid values converted to missing values
- Clearly implausible speeds above 50 km/h treated as corrupted records

#### Event-Date Parsing
Source dates may contain:
- single dates, e.g. `12.05.2018`
- date ranges, e.g. `16.-17.03.2018`

The cleaning logic extracts the final complete `DD.MM.YYYY` date and converts it to a proper datetime value.

#### Missing-Value Handling
Rows missing values required for age, speed, or date analysis are removed before EDA.

#### Column Standardization
- Unused columns removed
- Final analytical columns renamed using snake_case

## Data Cleaning Challenges Solved

### Challenge 1: Incorrect Athlete Age
**Problem**: Original logic calculated age as `2025 - birth_year`, which did not represent age at the historical event.

**Solution**: Calculate age using `event_year - birth_year`.

### Challenge 2: Event-Date Formats
**Problem**: Source data contains both single dates and date ranges.

**Solution**: Extract the final complete date using a regex pattern before datetime conversion.

### Challenge 3: Mixed / Invalid Speed Values
**Problem**: `Athlete average speed` contains values that may not parse cleanly as numeric.

**Solution**: Convert with `pd.to_numeric(..., errors="coerce")` and handle invalid values explicitly.

### Challenge 4: Implausible Speed Outliers
**Problem**: Some source values exceed realistic human running speeds.

**Solution**: Apply a conservative 50 km/h upper data-quality threshold.

### Challenge 5: Chained Assignment
**Problem**: Filtering and modifying DataFrame slices can trigger `SettingWithCopyWarning`.

**Solution**: Create explicit `.copy()` objects before transformation.
